# PinWall Desktop 0.1.2 产品需求文档

## 发布定位

`0.1.2` 是 `0.1.1` 之后的桌面端补丁版本，重点处理设置页体验问题，并把现有每日关怀、护眼、休息、下班等自动卡片收敛成统一提醒体系。这个版本不扩展市场、云同步或大型 Widget 生态能力，只把已经存在的能力整理得更清楚、更稳定、更适合日常使用。

一句话目标：

> 让设置页从“功能堆叠”变成“用户能快速理解和调整 PinWall 行为的控制台”，同时让关怀类能力以统一提醒方式出现，而不是不断铺到桌面上。

## 背景

`0.1.1` 已完成桌面交互修复、自动关怀卡片去重、本地 Widget 安全加固和权限展示。当前下一阶段最明确的问题是：

- 设置页面视觉不够精致。
- 设置项分布不够合理，用户需要长滚动才能找到目标。
- 关怀提醒、AI、额度监控、Widget 等能力在页面中权重接近，容易让核心设置被实验功能淹没。
- 一些设置项只有开关，没有足够的状态反馈或上下文信息。
- 每日关怀、护眼、休息、下班、天气、心情等系统关怀目前主要通过 `upsertSystemCard` 生成桌面卡片；这会让“提醒”和“长期便签”混在一起，也容易干扰桌面整洁度。

## 版本目标

### P0 目标

- 设置页信息架构清晰，用户能在 3 秒内判断主要设置分区。
- 核心设置优先呈现：语言、启动、快捷键、便签体验、关怀提醒。
- 实验功能降权：AI、额度监控、本地 Widget 保持可用，但不压过核心设置。
- 关怀类能力进入统一提醒体系，到点后使用右上角提醒窗口，而不是默认生成桌面卡片。
- 页面在默认设置窗口尺寸下不出现文字溢出、按钮拥挤或不自然的长表单堆叠。
- 设置项变更仍保持即时保存和重启后恢复。

### P1 目标

- 关怀提醒设置从多个碎片卡片合并为更紧凑的配置区。
- 每个分区有明确状态摘要，例如“已开启 4 项关怀提醒”“Widget 2 个已安装”。
- 高风险能力有更明显但克制的说明，例如 AI Key、Widget 网络/系统权限。
- 设置页视觉风格更贴近桌面工具：安静、紧凑、可扫描，而不是营销式大卡片。

## 非目标

以下内容不进入 `0.1.2`：

- 不做账号、同步、云备份。
- 不开放公开 Widget Marketplace。
- 不重做卡片主桌面交互。
- 不引入系统级原生通知中心集成；本版本继续使用 PinWall 现有右上角通知窗口。
- 不引入新的大功能模块。
- 不改变现有设置存储格式，除非为兼容或修复 bug 必需。
- 不新增复杂主题系统。

## 需求范围

### 1. 设置页信息架构重组

当前设置页已经分为 Basics、Note Experience、Care Reminders、Experimental，但实际体验仍是单列长滚动。

需求：

- 使用更清晰的分区导航。建议实现为左侧分区导航 + 右侧内容，窗口较窄时退化为顶部分段导航。
- 分区顺序固定为：
  1. 基础
  2. 便签体验
  3. 关怀提醒
  4. 实验功能
- 当前分区在导航中有明确选中态。
- 每个分区顶部展示标题、简短说明和状态摘要。
- 分区切换不丢失未完成输入状态。

验收标准：

- 用户无需滚动完整页面即可切换到任意分区。
- 默认设置窗口尺寸下，首屏能看见导航和当前分区的主要设置。
- 中英文下导航文字不挤压或换行失控。

### 2. 基础设置优化

范围：

- 语言切换
- 开机启动
- 全局快捷键

需求：

- 基础设置保持最靠前。
- 语言切换使用明确的分段控件。
- 开机启动显示当前状态和失败反馈位置。
- 快捷键录制区域需要有默认值、当前值和重置入口。
- 保存失败时不能只写 console，需要给用户可见反馈。

验收标准：

- 切换语言后，设置页和托盘菜单文案更新。
- 开机启动切换失败时，用户能看到失败提示。
- 快捷键修改成功后，当前值立即更新；修改失败时保留旧快捷键。

### 3. 便签体验设置补齐和整理

当前桌面外观相关 UI 被注释，`RELEASE_QA.md` 中仍包含透明度和背景自动切换检查，实际体验存在断层。

需求：

- 透明度由程序默认控制，不在设置页开放给用户调节。
- 背景自动切换如果暂不支持完整管理，应明确降级为隐藏或实验状态，不能在 QA 中作为稳定能力出现。
- 节日卡片开关保留，但需要显示两个开关的含义：
  - 中国节日
  - 国际节日
- 便签体验分区不应混入 AI 或 Widget 设置。

验收标准：

- 设置页不展示透明度滑块。
- 节日开关切换后重启仍保持状态。
- 若背景自动切换仍不可用，发布 QA 和设置页文案保持一致。

### 4. 关怀提醒设置整合

当前关怀提醒被拆成多个独立卡片，页面显得碎；运行时也主要通过系统卡片展示，和用户真正想长期保留的便签混在一起。

需求：

- 将关怀语气、休息、护眼、下班、心情、天气合并为一个或两个紧凑设置组。
- 每个提醒项至少包含：
  - 启用开关
  - 当前关键参数
  - 可配置参数入口
- 休息提醒显示间隔。
- 下班提醒显示时间。
- 天气作为主窗口常驻组件展示，不进入右上角提醒队列。
- 天气组件支持用户手动输入城市；未输入时可尝试自动定位当前城市。
- 天气组件展示当天实时天气和最近 7 天天气预报。
- 护眼提醒如果已有 interval 字段，应提供间隔配置；如果暂不开放配置，应显示固定策略。
- 心情打卡展示提醒时间，默认 09:10，用户可按自己的上下班节奏修改。
- 关怀提醒设置需要直接控制统一提醒调度；关闭某项后，该类提醒不再进入提醒队列。

验收标准：

- 所有关怀开关切换后能持久化。
- 默认窗口尺寸下，关怀提醒分区不需要超过两屏滚动。
- 关闭某个关怀项后，该项的详细参数仍可查看但呈现为次要状态。
- 自动关怀卡片仍保持 `0.1.1` 的去重行为。

### 5. 统一提醒体系

现有标准提醒由 `useReminders` 检查卡片的 `reminderTime`，到点后弹出右上角通知窗口。关怀类能力则由多个独立 hook 到点后创建或更新系统卡片。`0.1.2` 需要把这两类行为收敛为一个提醒模型。

提醒类型：

- 用户便签提醒：用户在便签上设置的提醒。
- 一次性系统提醒：只需要出现一次的系统关怀，例如今日天气关怀、一次性的每日问候。
- 周期系统提醒：需要长期重复的提醒，例如护眼、休息、加班关怀。
- 每日定时系统提醒：每天固定时间段触发的提醒，例如下班提醒、心情打卡。

需求：

- 建立统一的提醒调度入口，避免每个关怀 hook 独立创建桌面卡片。
- 到点后统一使用右上角通知窗口展示标题、内容、类型和操作按钮。
- 设置页开关直接决定对应提醒是否参与调度。
- 系统提醒应能区分一次性和周期性：
  - 一次性系统提醒：用户确认后清理本次提醒实例，不再保留临时卡片。
  - 周期系统提醒：用户确认后只标记本次完成，并计算下一次提醒时间，不删除提醒定义。
  - 每日定时系统提醒：用户确认后标记当天或当前时间段已处理，下一天或下一时间段仍可触发。
- 用户手写便签提醒默认不自动删除便签；确认后只标记提醒已触发。只有明确标记为“提醒型临时卡片”的系统生成内容，才能在确认后自动删除。
- 通知窗口需要支持“确认/知道了”和“查看/打开”两类行为：
  - 确认：完成本次提醒生命周期处理。
  - 查看/打开：如果提醒关联到桌面卡片，则唤起主窗口并定位或全屏该卡片。
- 如果通知自动消失，不能等同于用户确认；周期提醒不应因为 15 秒自动消失就永久跳过，至少应保留本次已弹出状态或进入合理的下次调度。

建议的初始分类：

| 提醒 | 类型 | 到点行为 | 确认后 |
|---|---|---|---|
| 用户便签提醒 | 用户便签提醒 | 右上角通知 | 标记 `reminderFired`，保留便签 |
| 护眼提醒 | 周期系统提醒 | 右上角通知 | 计算下一次时间，保留提醒定义 |
| 休息提醒 | 周期系统提醒 | 右上角通知 | 计算下一次时间，保留提醒定义 |
| 下班提醒 | 每日定时系统提醒 | 右上角通知 | 标记今日已提醒，明天可再次触发 |
| 加班关怀 | 周期系统提醒 | 右上角通知 | 保留下次加班提醒节奏 |
| 天气组件 | 主窗口组件 | 用户开启后常驻显示实时天气和 7 天预报 | 关闭设置后隐藏 |
| 心情打卡 | 每日定时系统提醒 | 右上角通知，可打开打卡卡片或入口 | 按用户设置时间提醒，默认 09:10；标记当前时间段已提醒 |

验收标准：

- 护眼、休息、下班、心情提醒不再默认铺成桌面系统卡片。
- 天气不作为提醒弹出，而是在主窗口中作为常驻组件展示。
- 右上角通知能展示关怀类提醒内容。
- 用户确认一次性系统提醒后，不会留下临时桌面卡片。
- 用户确认周期系统提醒后，下一周期仍能继续触发。
- 用户便签提醒确认后，便签仍保留。
- 关闭某个提醒设置后，该类型不会继续弹出。
- 应用重启后，已处理的一次性每日提醒不会在同一天重复弹出。
- 自动消失的通知不会造成一次性提醒或周期提醒的错误删除。

### 6. 实验功能降权

实验功能包括：

- AI 助手
- 额度监控
- 本地 Widget

需求：

- 实验功能分区需要明确标记为 Experimental / 实验功能。
- AI 和额度监控默认折叠，仅展示启用状态和摘要。
- API Key 输入必须保持 password 类型，不以明文展示。
- Widget 本地安装保留，但 Marketplace 只显示实验状态，不能表现为稳定商店。
- Widget 权限继续展示，并保留高风险权限视觉区分。

验收标准：

- 未启用 AI 时，不直接展示完整 API 表单。
- 未启用额度监控时，不直接展示模型添加表单。
- 本地 Widget 空状态、安装、启用、移除路径仍可用。
- 高风险 Widget 权限包括 `network`、`system`、`cards`、`ai`。

### 7. 视觉与交互质量

需求：

- 设置页应使用桌面工具风格：紧凑、克制、层级明确。
- 避免大面积同色系深蓝/紫渐变主导页面。
- 控件尺寸稳定，切换、展开和错误提示不应造成明显布局跳动。
- 按钮使用明确命令文案；危险操作使用红色但不过度强调。
- 长 URL、模型名、Widget 描述需要截断或换行策略。
- 设置页可键盘关闭，`Escape` 行为保持。

验收标准：

- 中文、英文下没有明显文字溢出。
- 长 API endpoint 和 Widget 描述不会撑破布局。
- 页面滚动条、分区导航和控件 hover/active 状态一致。
- 设置窗口重复打开关闭不会出现空白或重复实例。

## 技术任务建议

### 前端

- 重构 `desktop/src/components/SettingsPanel.tsx` 的结构，拆分分区组件。
- 为设置页增加分区导航状态。
- 梳理 `ap-*` 设置页样式，移除无用或过时样式。
- 移除设置页透明度控制 UI，透明度保持程序默认。
- 为设置保存失败增加用户可见反馈。
- 将关怀提醒设置整合成数据驱动渲染，减少重复 JSX。
- 设计统一提醒数据结构，至少能表达提醒来源、一次性/周期性、下次触发时间、确认后的生命周期动作。
- 将 `useEyeCareReminder`、`useRestReminder`、`useOffWorkReminder`、`useWeatherCare`、`useMoodCheckin` 从“创建系统卡片”迁移为“投递统一提醒”。
- 扩展通知窗口交互，区分确认、查看和自动消失。

### 测试

- 增加 SettingsPanel 的渲染测试，覆盖：
  - 分区导航
  - AI/额度折叠状态

- 增加统一提醒测试，覆盖：
  - 一次性系统提醒确认后清理本次实例
  - 周期系统提醒确认后计算下一次
  - 用户便签提醒确认后不删除便签
  - 关闭设置后不再调度对应提醒
  - 通知自动消失不触发删除逻辑
- 保留现有 store、widget、i18n 测试。
- 更新 `RELEASE_QA.md` 中设置页相关检查，使其匹配实际发布能力。

### 文档

- 新增 `desktop/releases/v0.1.2.md`，发布前再填充最终修复列表。
- 更新 `desktop/DESKTOP_ROADMAP.md` 的当前进展。
- 如果 `TEST_CASES.md` 继续保留，应更新第 9 节设置窗口内容，移除“开发中...”旧描述。

## 发布判断

可以发布 `0.1.2` 的条件：

- 自动检查全部通过。
- 设置页 QA 全部通过或仅有已记录的非阻断问题。
- 统一提醒生命周期 QA 全部通过。
- 没有新增主桌面交互回归。
- 没有新增 Widget 安全边界回退。
- 发布说明明确这是设置页体验和关怀提醒体系补丁版本。

建议发布标题：

> PinWall Desktop v0.1.2: Settings Polish and Care Reminders
