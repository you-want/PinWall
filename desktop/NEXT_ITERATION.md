# 下一轮：稳定的日常便签闭环

计划日期：2026-10-15。基于当前工作区继续开发，保留已有未提交改动。

## 本轮范围与顺序

1. **测试与启动基线**：Playwright 在页面加载前注入受控 Tauri IPC 适配器；只模拟原生边界，继续使用真实 React、Zustand 和 tauri-store 前端代码。未知 command 必须报错。浏览器持久化使用测试上下文的 localStorage，不接触真实 AppData。原生 store 统一由入口启动，并在加载完成后渲染业务页面。
2. **便签编辑**：复用新建弹窗，支持编辑标题、正文、颜色及已有提醒的时间/开关；保存为一个 store 动作，取消不修改数据。编辑不改变卡片 id、类型、位置和打卡记录；仅当提醒配置改变时重置已触发标记。补齐中英文、键盘保存/取消和焦点管理。
3. **布局恢复**：移除启动时的自动排列，保留用户位置；保留主动“整理排列”操作。用两张卡片验证恢复，避免单卡片测试漏掉旧的自动排列分支。
4. **回归门禁**：保留原有 UI 测试，增加创建→编辑→拖动→重新加载、取消编辑、提醒编辑、删除后恢复、主动排列等流程；接入 Desktop CI。

本轮不修改持久化 schema、Rust command 或原生权限；浏览器测试不代替原生磁盘、窗口行为和签名验收。

## 第二轮 A：设置事务与便签备份（2026-10-15）

本轮处理优先级 3 的本地数据可靠性，分为以下可验证步骤：

1. 设置统一经 Rust 读取和提交。原生锁保护 revision 比较与原子替换；前端冲突后重新读取并重放单项操作，最多 12 次。覆盖背景数组修改、设置页、天气日期和自启动规范化，取消整文件 `saveSettings` 调用。
2. 设置和卡片 schema version 为 1。设置仍保持平铺 JSON，使原生托盘的快捷键读取兼容；旧设置在首次成功保存时写入版本。卡片在插件加载前验证、补齐旧字段并原子迁移，保留坐标、提醒状态及层级。所有 store 启动之前执行预检。
3. 损坏 JSON 或字段类型错误时，原文件保持不变，在同目录创建首次 `.corrupt-backup` 副本并阻止启动/覆盖；备份失败也会阻止继续。未来版本只报告升级提示。非不存在的 IO 错误不回退为默认值。错误信息和迁移日志不含正文、密钥或个人路径。
4. “设置 → 基础 → 便签备份”提供原生文件选择的导出与合并恢复。只导出允许的便签字段；不包含设置、密钥、组件或任意额外字段。文件上限 20 MiB，卡片上限 10,000；验证通过后才询问合并，取消不修改数据。同 ID 保留本地便签，导入提醒关闭，重复导入幂等。
5. 恢复在原生插件 store 锁内合并最新状态，先原子保存 `.before-restore` 快照，再原子替换卡片文件并广播。提交前失败不修改当前状态；提交后广播失败明确提示退出重开，不伪称已回滚。
6. 原生 command 按窗口标签限制：设置读取/预检允许 main、settings、notification；写入/便签备份仅 main、settings。导入导出路径由原生对话框取得，拒绝符号链接和不安全路径，导出不能覆盖 AppData 内的运行文件；未新增插件权限或依赖。

## 第二轮 B：日常保存与密钥迁移（2026-10-15）

本轮继续处理优先级 3，先完成纯服务/原生临时目录测试，再接入 UI 与浏览器流程：

1. 用独立的原生卡片仓库接管日常保存、读取和备份恢复；插件不再加载 cards 文件。保留旧文件位置和卡片 schema version 1，新增 revision；所有提交在同一原生锁内读取最新状态、按卡片字段合并、验证并原子替换。
2. 前端保留乐观草稿和待提交增量，收到原生事件后重放未确认修改；连续拖拽合并未发送更新。写入失败显示重试入口，草稿留在内存中；重试沿用原 mutation ID，防止响应丢失后重复提交。远端删除的卡片不会被旧 update 复活。获得焦点时重新读取，补偿错过的事件。
3. Keychain 采用不可变密钥包，先写入并读回验证，再提交设置引用，最后尽力清理旧包。设置提交失败清理新包、保留旧引用；拒绝访问保留旧明文文件。设置升级到 schema version 2，AI 和额度监控调用方继续使用内存中的密钥。启动预检不访问密钥，通知窗口仅取得无密钥设置；非 macOS 不回退明文保存。
4. 新增 `cards_read` / `cards_patch` 并校验窗口与输入；读取允许三个应用窗口，写入仅 main/settings。未扩大 capability，macOS 增加 `security-framework` 依赖。所有测试密钥均为假数据，自动化不访问用户 Keychain 或真实 AppData。

### 第二轮 C：统一提醒调度（2026-10-15）

将便签提醒、喝水、护眼、休息、下班、心情、天气和跨日重置接入 `reminderScheduler` 共享心跳。调度器只有一个可取消的 timer，按订阅间隔触发回调；回调失败不会中断其他提醒，异步回调不会重叠。订阅全部释放后自动停止，睡眠或长时间后台运行后按当前时间补检。额度监控仍保留独立的网络刷新周期，因为它不是提醒调度的一部分。

- [x] 新增可注入时钟和 timer 的调度器单测，覆盖共享心跳、自动停止、慢回调防重入。
- [x] 现有提醒 hook 保留原有去重、文案、设置和通知窗口行为，仅替换定时器生命周期。
